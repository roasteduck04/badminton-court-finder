# CourtVisionNet Handover — 2026-10-31

## Why everything changed

A full code review found that the Run 7 result (PCK@10 = 90.5%, MRE = 12.91 px) does not measure generalization:

- **Frame leakage.** Every Roboflow test frame had a training frame from the same video ±1–2 frames away. Copying the labels of the most similar training image scored 95.1% PCK@10 on that test set, beating the model. On the 7 genuinely held-out photos, Run 7 scored 9%.
- **Inconsistent labels.** The court is symmetric under mirroring and 180° rotation, and the sources disagreed:
  - Blender labels were mirrored and fixed to the world.
  - The hand labels were mostly rotated 180° relative to Roboflow.
  - One Roboflow video was mirrored.
  - The fixed `FLIP_PAIRS` augmentation relabeled side views wrongly.
- **Decoding and loss bugs.** The soft-argmax grid did not match the target convention, and global soft-argmax pulled predictions toward the centre. The geometric losses had no effect, or worked against correct labels (the ratio loss is not perspective-invariant).
- **Pipeline bugs:**
  - Augmentation ran after the derived channels were computed.
  - Images were squashed to a square.
  - There was no input normalization, and the backbone freeze also froze the random FPN.
  - Nothing was seeded, and checkpoints were selected on total validation loss.
  - The current code could not load the best checkpoint.
- **Security.** The annotator server listened on all interfaces, allowed path traversal on read, write and delete, and served `.env`.

The old numbers, `data/colab_data` and the Run 1–7 table in `handover-2026-08-18.md` should not be cited.

## What is in place now

| Area | State |
|---|---|
| Labels | `court_geometry.canonicalize` is the single convention: positive orientation, and row 0 → row 5 points up or right (end-on view: K0 = near-left). It is applied in the annotators, converters, dataset build and every augmentation. |
| Data | `scripts/prepare_colab.py` builds `data/colab_data_v2`: group splits (whole videos or sessions, with visually identical groups merged), a hash manifest, residual QA, and **0 cross-split near-duplicates**. |
| Splits | train 1262 (58 manual / 686 Roboflow / 518 Blender), val 35, test_real 41, test_roboflow 46 |
| Model | Letterboxed input; augment, then compute channels; in-model normalization; JS heatmap loss + coordinate loss + differentiable-homography reprojection loss + symmetric (rot180) option; pixel-centre convention; argmax + DARK decoding; MAGSAC homography refinement at inference |
| Training | `python -m src.training.train --config configs/baseline.json --set seed=N`. Seeded and exactly resumable; selects on real-image val PCK@10; v2 checkpoints carry config, git SHA and history. Ablation configs are in `configs/` (see its README). |
| Evaluation | Original-pixel errors; PCK in px and normalized by court diagonal; KLA; AUC; court-metre error; RANSAC reprojection; court IoU; PCR; visibility P/R/F1; bootstrap CIs; per-source and per-keypoint breakdowns; nearest-neighbour baseline script |
| Synthetic | Blender default cube removed; real net and box geometry; ray-cast occlusion; 7 camera strategies with roll, 13–85 mm lenses, partial framing and 4 aspect ratios; varied floor and line colours; per-image seeds; `synthetic_augment.py` for lens distortion, blur, noise and JPEG |
| Security | Servers bind to 127.0.0.1, check paths stay inside their folders, check Origin and Host headers, and serve no repo files |
| Hygiene | `pytest tests/` works without Blender; pinned requirements; `pyproject.toml`; CI workflow; ruff clean |

## Reference numbers on the new splits (sanity only)

| | test_real PCK@10px | test_roboflow PCK@10px |
|---|---|---|
| Nearest-neighbour label copy | 0.4% | 1.2% |
| Legacy Run 7 checkpoint (old labels, leaked training) | 25.9% | 24.0% |

Run 7 is not a fair baseline: it learned the old mirrored labels and saw these videos and sessions during training. Retraining is required.

On test_roboflow, KLA@0.1 (10% of the image diagonal, the CourtKeyNet metric) is 100% even for the label-copy baseline. Broadcast views from different events look alike, so lead with px and court-normalized PCK.

## Next steps

1. **Re-render synthetic data** with the fixed generator (now with per-image auto-FOV, 2026-11-01), then rebuild:
   ```
   python scripts/generate.py render --count 2000
   python scripts/generate.py augment --out data/blender_aug
   python scripts/prepare_colab.py --out data/colab_data_v2 --overwrite --extra-synthetic data/blender_aug
   ```
   The current `colab_data_v2` still contains the old renders (default cube, no net, no occlusion flags).
2. **Train the baseline with 3 seeds** on RunPod (`docs/runpod.md`, `scripts/runpod/run_experiments.sh`) or Kaggle. Zip `data/colab_data_v2`, upload it as a dataset, and set `REPO_REF` in the notebook to the commit you push. Watch `rot180_fraction` in the logs: it should fall well below 0.5. If it stays near 0.5, the symmetric loss is hiding orientation learning; compare against `no_symmetric`.
3. **Run the ablations** in `configs/` (rgb_only, no_synthetic, no_reproj, mse_heatmap, no_symmetric, sigma6), each with ≥3 seeds. Report mean ± std on test_real and test_roboflow separately, next to the nearest-neighbour baseline.
4. **Collect more held-out real data.** test_real is one hall (new sessions and devices, not a new venue) plus 4 web images, and test_roboflow is only 2 events. Annotate 100+ images from unseen venues and angles before claiming generalization.

The prioritized research plan (baselines, line-aware refinement, backbones, semi-supervised video) is in `docs/improvement-plan.md`.
