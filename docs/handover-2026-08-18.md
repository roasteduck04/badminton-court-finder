## What Went Wrong in Run 6

AMP (mixed precision / float16) caused numerical overflow in the heatmap loss. The MSE sum over 30×160×160 = 768,000 values exceeds float16 max (~65,504) when heatmap_weight=100. Train loss exploded to ~458,400 while val loss (computed in float32) stayed at ~6.0. Fixed by disabling AMP (commit 80cd2e0).

## What Went Wrong in Run 4

The model learned nothing. Root cause: heatmap loss contributed only 0.9% of total loss. Without heatmap gradients, soft-argmax produced uniform weights → every keypoint predicted center (0.5, 0.5) → MRE stuck at ~201px.

## Key Fixes Applied (cumulative)

1. **`heatmap_weight`: 5 → 100** (commit d68a321)
   - Makes heatmap gradient 20x stronger, comparable to seg/offset/vis losses

2. **Learnable `beta` parameter (init=10.0)** in soft-argmax (commit d68a321)
   - `F.softmax(flat * self.beta, dim=-1)` — amplifies small heatmap differences

3. **OneCycleLR scheduler** replacing CosineAnnealing (commit 59c7ce1)
   - Built-in warmup + aggressive peak + smooth anneal

4. **Thicker seg mask lines (3px → 5px)** (commit 59c7ce1)
   - More gradient signal for segmentation head

5. **AMP disabled** (commit 80cd2e0)
   - Float16 overflows with heatmap_weight=100
