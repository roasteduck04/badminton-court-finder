## What Went Wrong in Run 4

The model learned nothing. Root cause: heatmap loss contributed only 0.9% of total loss. Without heatmap gradients, soft-argmax produced uniform weights → every keypoint predicted center (0.5, 0.5) → MRE stuck at ~201px.

It's unclear why Run 3 worked but Run 4 didn't with the same architecture. Possibly Run 3 was run interactively with different state, or there was a code version mismatch.

## Fixes Applied for Run 5 (commit d68a321)

1. **`heatmap_weight`: 5 → 100** (in `src/training/config.py` and `src/models/losses.py`)
   - Makes heatmap gradient 20x stronger, comparable to seg/offset/vis losses
   
2. **Learnable `beta` parameter (init=10.0)** in soft-argmax (`src/models/keypoint_head.py`)
   - Multiplies heatmap values before softmax: `F.softmax(flat * self.beta, dim=-1)`
   - Amplifies small heatmap differences so early training gets useful gradients
   - Learnable so the model can adjust sharpness during training

## Changes for Run 6

Applied in code, ready to push and run:

1. **AMP (mixed precision)** — ~1.5x speedup on T4, more epochs in the time budget
2. **OneCycleLR (max_lr=1e-4)** — replaces CosineAnnealing at 3e-5; more aggressive LR with built-in warmup
3. **PCK@5 metric** — tracked alongside PCK@10 in validation, test, and training history plots
4. **Thicker seg mask lines (3px → 5px)** — seg_loss is the #1 remaining loss; thicker targets give more gradient signal
5. **Training history plot** — now 2x2 grid with PCK and MRE curves alongside loss plots

### Still worth trying later

- **Improve visibility head** — currently a single AdaptiveAvgPool → Linear; adding a second FC layer with dropout, or per-keypoint feature pooling from heatmap peaks
- **Stronger augmentation** — hue/saturation jitter, more aggressive perspective transforms (scale up to 0.2)
- **More data** — 527 training images is small; more annotated frames would help generalization
